# v1.6.1 更新日志：mc_input 游戏输入工具

本版本将原有的 `click_game_window` 重构为 `mc_input`：一个面向 AI 的单入口键鼠输入工具。它不再局限于「点一下」，而是以命令形式接收一整串输入步骤，一次调用即可完成点击、长按、拖拽、滚轮、视角转动、文本输入和等待的组合操作。

与 `jsonui_debugger`、`mc_profiler` 一致，采用单工具命令形态，先用 `/help` 按需查看说明，避免 MCP 工具列表膨胀。

## 支持的步骤类型

| 步骤 | 用途 |
| --- | --- |
| `click` | 点击、长按、双击，可带修饰键；省略坐标即在指针当前位置按下 |
| `drag` | 按住并拖动，中途产生插值移动事件 |
| `move` | 移动指针，用于悬停或拖拽前定位 |
| `scroll` | 滚轮，切换热键栏或滚动列表 |
| `look` | 相对转动视角，游戏独占指针时唯一有效的移动方式 |
| `key` | 按键、组合键与长按 |
| `text` | 文本输入，走 Unicode 通道 |
| `wait` | 等待，让界面动画或游戏刻推进 |

## 坐标仍为百分比

坐标一律是客户区百分比 `0.0-1.0`，与 `capture_game_window` 的截图完全同构：`(0,0)` 左上，`(1,1)` 右下。本版本未引入像素坐标——窗口尺寸一变化，像素值就会失效并污染上下文理解。

## 长按与拖拽

长按有三种粒度：

* `hold_ms`：单次调用内按住指定毫秒，适合挖掘方块、蓄力。
* `action: "down"` + `wait` + `action: "up"`：在同一批次里按住的同时执行其他步骤。
* `leave_held: true`：跨调用保持按下（例如按住 W 前进的同时去查日志），结束后必须用 `/release-all` 收尾。

拖拽按 Minecraft 的判定方式实现：移动到起点 → 按下 → 停顿 → 插值移动 → 停顿 → 松开。中间的插值移动是必需的，只有起止两个事件会被游戏当成一次普通点击。

## 输入法处理

游戏中的 WASD 是动作输入而非打字，输入法开启时按键会被 IME 吞掉或转为候选词。新增 `ime` 选项，默认 `suppress`：批次期间将目标窗口切换到英数直通模式并关闭输入法，结束后恢复原状。`text` 步骤走 Unicode 通道，不受此项影响，中文照常输入。如需保留原有输入法状态，设置 `ime: "keep"`。

## 安全与容错

* 焦点守卫：每一步前复核目标窗口仍在前台，一旦被其他窗口抢走立即中止，不会把后续输入打到你正在使用的窗口上。
* 自动释放：任何退出路径（报错、超时、失焦、游戏退出）都会逆序释放已按下的键鼠，并在返回值中如实列出，不会留下「角色一直往前走」的卡键状态。
* 参数全量前置校验：整批步骤先全部校验再开始执行，不存在「跑到第五步才发现字段拼错」。
* `dry_run`：只校验并换算坐标、不投递任何输入，可零风险自检。
* 结构化错误：失败时返回明确错误码（`FOCUS_DENIED` / `FOCUS_LOST` / `POINTER_MODE_MISMATCH` / `PRIVILEGE_BLOCKED` / `DESKTOP_UNAVAILABLE` 等）与恢复建议，并说明执行到第几步、哪些输入已被释放。

单批次上限 64 步，默认时间预算 30 秒。`capture: "end"` 可在同一次调用中附带一张执行后的截图。

## 使用方式

```json
{
    "op": "/run",
    "args": {
        "steps": [
            {"do": "key",   "keys": "esc"},
            {"do": "wait",  "ms": 200},
            {"do": "click", "at": [0.5, 0.42], "button": "right"},
            {"do": "drag",  "from": [0.31, 0.55], "to": [0.62, 0.55]},
            {"do": "text",  "value": "/gamemode creative"},
            {"do": "key",   "keys": "enter"}
        ],
        "capture": "end"
    }
}
```

调用 `/state` 可查询窗口尺寸、前台状态、指针是否被游戏独占、输入法状态以及当前仍按住的键，用于决定使用绝对坐标还是 `look`。

注意：调用成功仅代表输入已投递到系统队列，不代表游戏已经响应。需要确认结果时请配合 `capture_game_window` 或日志。

## 不兼容变更

`click_game_window` 已移除，请改用 `mc_input`。原先的 `click_game_window(x, y)` 等价于：

```json
{"op": "/click", "args": {"at": [x, y]}}
```

坐标语义完全不变，仍是 `0.0-1.0` 百分比。

## 其他修复

* 修复窗口位于副屏时点击坐标偏移的问题（改用虚拟桌面归一化）。
* 修复抢占前台失败后仍然继续发送输入的问题，现在会在投递任何事件之前中止。
* 截图、窗口样式与输入注入改为共用同一份窗口解析规则，避免三条路径定位到不同窗口。
